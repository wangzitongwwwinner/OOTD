# M1-01 微信登录与会话恢复实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立仅含微信一键登录的生产主链路，覆盖协议确认、可信微信身份、用户创建/查询、版本化缓存和会话恢复。

**Architecture:** 小程序调用 CloudBase `api` 云函数时只提交协议版本和确认时间，云函数从平台上下文读取 `OPENID/APPID`，不接受客户端身份字段。服务端仓储保存内部微信标识，响应只返回公开用户摘要；客户端缓存带 schemaVersion、用户隔离键和过期时间，恢复时通过云函数重新确认。

**Tech Stack:** Taro 4.2.0、React 18、TypeScript、Vitest/Testing Library、CloudBase Node.js 20.19、Zod 4。

## Global Constraints

- MVP 仅保留微信一键登录，不实现手机号、短信验证码或自建密码登录。
- 未勾选用户协议与隐私政策时不得发起云函数请求。
- 服务端只信任 CloudBase 平台身份，不接受客户端 `userId`、`openId` 或会话 Token。
- `wechatOpenId` 不返回小程序、不写日志；错误只返回稳定错误码和用户可理解文案。
- 整个 MVP 仅使用 `ootd-ai-dev`；未获得单独授权前不部署云函数、不创建或写入云端集合。
- 未经用户再次确认不执行 Git commit 或 push。
